Torabo-Studio タブ別機能紹介

接続すると、そのキーボードのファームウェアが対応している機能のタブだけが表示されます。 どのタブも設定は BLE 経由で即反映・本体に保存され、再フラッシュは不要です。 キーマップ以外のタブは torabo-tsuki_ext_FW の該当スニペットを含めた拡張ファームウェアが前提です。

⚠️ ハードウェアについての大事な注意：トラックパッド・エンコーダ・LED のタブは、 下の各項目に書いた特定のハードウェア構成での動作を想定したものです。 市販の任意のトラックパッドやエンコーダ、LED を繋いで自動的に使えるようになるわけではありません。
キーマップ トラックボール トラックパッド エンコーダ LED タップ反応 マクロ コンボ バックアップ

キーマップ

ZMK Studio 標準のキーマップ／レイヤー編集そのままです。レイヤーを選んでキーをクリックし、 割り当てを変えて保存します。このタブだけは拡張ファームウェアなし（標準ファームウェア）でも使えます。

必要なもの: torabo-tsuki 本体のみ（標準ファームウェアで可）

トラックボール

レイヤー×軸（X/Y）ごとに、ボールの動きへ「カーソル移動／スクロール／無効」と速度・向きを割り当てます。 ボールを動かすと一時的にマウス用レイヤーへ切り替わる「一時レイヤー（オートマウス）」と、 スクロールを止めた後も勢いに応じて滑り続ける慣性スクロールもここで調整します。

必要なもの: 本体内蔵のトラックボール ＋ 拡張ファームウェア

トラックパッド

レイヤーごとに、なぞる操作（スワイプ）の横方向・縦方向へ「カーソル移動／スクロール／音量／明るさ」などを割り当てます。 たたく操作（単タップ・ダブルタップ・2本指タップ・長押し）への動作割り当てと、慣性スクロールにも対応しています。

必要なもの: torabo-tsuki LP 拡張用トラックパッド（のぎけす屋・BOOTH） ＋ 拡張ファームウェア。 トラックボールを載せている側にトラックパッドも付ける場合は、さらに bmp-boost 用拡張ボード（sekigon-gonnoc 氏が公開されている設計データを JLCPCB などの基板業者へ自分で発注したもの）が必要です。 拡張ボードからトラックパッドへ繋ぐ短いケーブルとしては FFC ケーブル（6ピン・0.5mm ピッチ・30mm 長・A タイプ）を購入しました。

エンコーダ

ロータリーエンコーダの右回し・左回し・押し込みを、レイヤーごとに割り当てます（音量・ズーム・左右キー・カスタムなど）。 エンコーダはキーマップ上のキーではないため、キー位置を消費しません。

必要なもの: 1U ホイールエンコーダー THQWGD001（tarohayashi・BOOTH）を、 自作の FFC 接続基板で本体に接続した構成 ＋ 拡張ファームウェア。 市販のエンコーダをそのまま挿して使えるものではありません。

LED

拡張基盤の3色 LED を、左右それぞれ独立にルールベースで設定します。 「相方（もう半分）を見失った」「電池残量が少ない」「修飾キー押下中」「BLE プロファイル切替」などのきっかけに、 色と光り方（点灯・ゆっくり点滅・ダブル点滅など）を割り当て、上から順に最初に当てはまったルールが表示されます。

必要なもの: bmp-boost 用拡張ボード（sekigon-gonnoc 氏が公開されている設計データを JLCPCB などの基板業者へ自分で発注したもの） ＋ 拡張ファームウェア

タップ反応

Hold-Tap（&mt / &lt）の判定時間と、キーボードのデバウンス時間を再ビルドなしで調整します。 プリセット（標準／ロール誤爆防止など）を選ぶだけでも使え、詳細設定で個別パラメータも詰められます。

作った理由：Mod-Tap の Shift が速いタイピングで誤認識され、意図せず大文字が入力されてしまうのを、 ビルドし直さずにその場で判定時間を調整して追い込めるようにするためです。

必要なもの: 拡張ファームウェアのみ（追加ハードウェア不要）

マクロ

各スロットに「キーを順に入力する手順」を登録します。keymap 側に &dmac 0 などを置いたキーで再生されます。 既存 keymap ファイルからの取り込みにも対応しています。

作った理由：ZMK の通常のマクロは内容を変えるたびにファームウェアのビルドと書き込みが必要になるため、 マクロの中身だけを BLE でその場で書き換えられるようにしました。

必要なもの: 拡張ファームウェアのみ（追加ハードウェア不要）

クリックで原寸表示

コンボ

複数のキー位置の同時押しに、1つの動作（キー入力・モード切替・マクロ再生）を割り当てます。 タイムアウトや直前アイドル時間、有効になるモードの指定など、誤発火を抑える調整もできます。

作った理由：マクロと同じく、コンボの定義変更のたびにファームウェアを焼き直さなくて済むようにするためです。

必要なもの: 拡張ファームウェアのみ（追加ハードウェア不要）

バックアップ

キーマップと独自設定の一式を JSON 1ファイルに書き出し・復元します。設定を作り込む前後で取っておくと安心です。

キーマップ（ビヘイビア）の ID は個体ごとに採番が異なるため、そのままでは他のキーボードへ設定を移せません。 バックアップに ID と名前の対応表を持たせて読み替えることで、別の個体への設定移植もできるようにしています。

必要なもの: 特になし（接続できれば利用可）
